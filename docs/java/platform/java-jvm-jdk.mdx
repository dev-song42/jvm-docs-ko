## 학습 목표

- Java로 코드를 작성한다는 말과 JDK를 설치한다는 말의 차이를 설명합니다.
- JVM과 표준 라이브러리가 실행 환경에서 맡는 역할을 구분합니다.
- JDK에 개발 도구와 실행에 필요한 구성 요소가 함께 들어 있는 이유를 이해합니다.

선수 지식은 없습니다. 이 글은 [Java 로드맵](../../roadmap.mdx#1-java-플랫폼과-실행-구조)의 **1.1**입니다. 컴파일과 실행의 상세 단계, 오류 구분은 다음 항목인 **1.2 소스 컴파일, 바이트코드, JVM 실행**에서 다룹니다.

## 핵심 개념

“Java를 배운다”, “Java를 설치한다”, “Java로 프로그램을 실행한다”는 말에는 서로 다른 대상이 들어 있습니다. **Java 언어는 코드를 표현하는 규칙이고, JVM은 프로그램을 실행하는 가상 머신이며, JDK는 개발과 실행에 필요한 소프트웨어를 묶은 도구 모음입니다.** 여기에 미리 만들어진 기능을 제공하는 표준 라이브러리가 함께 쓰입니다.

### Java: 프로그램을 표현하는 언어

Java 언어는 변수를 선언하는 방법, 계산식을 쓰는 방법, 클래스를 정의하는 방법처럼 소스 코드의 문법과 의미를 정합니다. 예를 들어 `int total = 2 + 3;`에서 정수 타입과 덧셈, 변수에 값을 저장하는 규칙은 언어의 영역입니다.

이 규칙의 기준 문서는 **JLS(Java Language Specification)**입니다. JLS는 언어를 강한 타입 검사와 정적 타입 검사를 갖춘 언어로 설명합니다. 여기서 정적 타입 검사는 프로그램을 실행하기 전에 타입 규칙을 검사한다는 뜻입니다. 지금은 타입의 세부 분류보다 **언어 사양이 코드의 의미를 정한다**는 점에 집중하면 됩니다. [근거: JLS 1장][jls-intro]

Java라는 말은 언어뿐 아니라 플랫폼을 가리킬 때도 있습니다. **Java SE(Standard Edition)**는 언어·가상 머신 사양과 표준 API 등을 포괄하는 기본 플랫폼입니다. 이 글에서는 문법을 말할 때는 “Java 언어”, 실행과 공통 기능까지 말할 때는 “Java 플랫폼”으로 구분합니다.

### JVM: 정해진 형식의 프로그램을 실행하는 가상 머신

**JVM(Java Virtual Machine)**은 프로그램 실행을 위한 명령과 메모리 사용 규칙 등을 정의한 추상적인 컴퓨터입니다. 실제로 프로그램을 실행할 때는 이 규칙을 구현한 소프트웨어가 동작합니다. 따라서 “JVM 사양”과 “설치된 JVM 구현체”도 구분해야 합니다.

JVM이 다루는 것은 Java 소스 문법 자체가 아니라 **클래스 파일 형식**입니다. 클래스 파일에는 JVM 명령인 바이트코드와 실행에 필요한 부가 정보가 담깁니다. 어떤 언어로 작성했든 유효한 클래스 파일을 만들 수 있다면 JVM에서 실행하는 언어가 될 수 있습니다. JVM을 Java 언어와 같은 것으로 보면 이 관계를 설명하기 어렵습니다. [근거: JVMS §1.2][jvms]

이 글에서는 클래스 파일을 “JVM이 받아들일 수 있도록 준비된 프로그램 형식” 정도로 이해하면 충분합니다. 파일 내부 구조와 바이트코드 명령은 여기서 외우지 않습니다.

### JDK: 개발 도구와 실행 환경을 함께 제공하는 묶음

**JDK(Java Development Kit)**는 Java 프로그램을 개발하고 실행할 때 쓰는 소프트웨어 묶음입니다. 대표적인 구성 요소는 다음과 같습니다.

- `javac`: Java 소스 코드를 클래스 파일로 만드는 컴파일러입니다.
- `java`: JVM을 시작하고 애플리케이션 실행을 요청하는 실행 도구입니다.
- 표준 라이브러리와 JVM 구현체: 프로그램이 공통 기능을 사용하며 실행될 수 있도록 합니다.

`javac`와 `java`는 JDK에 들어 있는 서로 다른 도구입니다. 또한 `java` 명령은 JVM을 시작하는 진입점이므로, 명령 이름 자체와 JVM 전체를 같은 것으로 보면 안 됩니다. JDK를 준비하면 컴파일러만 얻는 것이 아니라 실행에 필요한 구성 요소도 함께 얻습니다. [근거: dev.java의 JDK 설명][getting-started], [javac Description][javac], [java Description][java]

## 동작 원리

### 역할을 나누어 보기

프로그램에서 어떤 기능을 만났을 때 “문법인가, 제공된 기능인가, 실행을 맡는가, 개발 도구인가”를 나누면 용어가 덜 헷갈립니다.

| 구분 | 맡은 일 | 예시·기준 |
|---|---|---|
| Java 언어 | 소스 코드의 문법과 의미를 정합니다. | JLS |
| 표준 API | 출력 등 프로그램이 호출할 공통 기능의 사용법과 동작을 정합니다. | `System.out` |
| JVM | 클래스 파일의 명령을 실행하는 규칙을 제공하며, 구현체가 실제 실행을 맡습니다. | JVMS |
| JDK | 개발 도구와 실행에 필요한 구현을 함께 제공합니다. | `javac`, `java` |

표는 위에서 아래로 역할을 비교해 읽습니다. 앞의 세 행은 서로 다른 책임을, 마지막 행은 개발자가 사용하는 배포 묶음을 나타냅니다. **실행 순서나 설치 디렉터리의 포함 관계를 나타낸 표는 아닙니다.** [JLS][jls-intro], [JVMS][jvms], [System API][system-out], [JDK 설명][getting-started]을 근거로 직접 구성했으며, 전체 도구 목록과 JVM 내부 구성은 생략했습니다.

API는 프로그램이 다른 기능을 호출할 때 따르는 약속입니다. 표준 API의 실제 기능은 표준 라이브러리 구현으로 제공됩니다. 예를 들어 `System.out.println(...)`은 언어에 새 출력 문법을 추가한 것이 아니라, 제공된 API를 Java의 메서드 호출 문법으로 사용하는 표현입니다.

다만 언어와 라이브러리가 완전히 무관한 것은 아닙니다. `String`처럼 언어와 특별한 관계를 갖는 표준 클래스도 있습니다. JLS는 이런 관계를 설명하지만, API의 전체 계약은 API 문서에서 확인하도록 구분합니다. [근거: JLS §1.4][jls-api]

### 실행 환경과 JRE의 관계

애플리케이션은 JVM만으로 필요한 모든 기능을 얻지 않습니다. 예를 들어 화면에 값을 출력하는 프로그램에는 표준 출력 API의 구현도 필요합니다. JVM 구현체, 필요한 라이브러리와 지원 파일처럼 **실행에 필요한 구성을 함께 제공하는 환경**을 생각해야 합니다.

**JRE(Java Runtime Environment)**는 이런 실행 환경을 가리키는 용어이며, 개발 도구를 제외한 실행용 배포 묶음의 이름으로도 사용되어 왔습니다. 따라서 JRE와 JVM은 같은 말이 아닙니다. JVM은 실행 환경의 핵심 구성 요소입니다. [근거: dev.java의 JRE 설명][getting-started], [JEP 220의 기존 런타임 구성 설명][jep-220]

JDK는 실행 환경에 개발 도구까지 제공한다고 이해하면 좋지만, 이를 “JDK 안에 반드시 별도의 `jre` 폴더가 있다”는 설치 규칙으로 외우면 안 됩니다. 모듈화 이후의 JDK 이미지는 개발 도구까지 포함한 런타임 이미지로 구성됩니다. 여기서 **이미지**는 실행에 필요한 파일을 모아 놓은 배포 구성을 뜻합니다. [근거: JEP 220, New run-time image structure][jep-220]

필요한 모듈과 그 의존성을 모아 맞춤 런타임 이미지를 만드는 `jlink`라는 도구도 있습니다. 따라서 개발용으로 JDK를 사용하는 것과, 실행할 곳에 어떤 구성 요소를 배포할지는 구분할 수 있습니다. 이 글에서는 이런 구성이 가능하다는 점까지만 다룹니다. [근거: jlink Description][jlink]

## 예제

### 작은 프로그램에서 역할 찾기

아래 예제는 두 수를 더한 결과를 출력합니다. `class`와 `main`의 자세한 문법은 이후에 익히고, 지금은 언어로 작성한 부분과 제공된 기능을 호출한 부분을 나누어 봅니다.

```java title="PlatformExample.java"
public class PlatformExample {
    public static void main(String[] args) {
        int total = 2 + 3;
        System.out.println("total = " + total);
    }
}
```

`int total = 2 + 3;`은 Java 언어의 변수 선언과 계산 규칙을 사용합니다. `System.out.println(...)`은 표준 출력 기능을 사용합니다. `System.out`은 표준 출력 스트림이고, 여기서 호출하는 `println(String)`은 문자열을 출력한 뒤 줄을 끝냅니다. [근거: System.out][system-out], [PrintStream.println(String)][println]

JDK가 준비되어 있고 터미널에서 그 JDK의 `javac`와 `java`를 사용할 수 있다면, 파일을 저장한 디렉터리에서 다음 두 명령으로 확인할 수 있습니다.

```bash title="컴파일과 실행"
javac PlatformExample.java
java -cp . PlatformExample
```

출력은 다음과 같습니다.

```text title="실행 결과"
total = 5
```

첫 명령은 JDK의 컴파일러를 사용하고, 두 번째 명령은 실행 도구를 통해 JVM에서 프로그램을 실행합니다. `-cp .`은 이 예제의 클래스를 현재 디렉터리에서 찾도록 지정합니다. 이때 프로그램은 표준 라이브러리의 출력 기능도 함께 사용합니다. [근거: javac Description][javac], [java Description 및 Standard Options][java]

예제에서 구분할 대상은 **소스의 표현 규칙, 호출한 표준 기능, 사용한 개발 도구, 실행을 맡은 JVM**입니다. 클래스 파일이 만들어지고 읽히는 상세 과정과 명령 오류는 1.2에서, 클래스패스는 1.3에서 이어서 다룹니다.

## 주의할 점

### 플랫폼 독립성은 실행 환경이 필요 없다는 뜻이 아닙니다

JVM 사양과 클래스 파일 형식은 특정 운영체제나 CPU에 묶이지 않도록 정의되어 있습니다. 그러나 실제로 설치하는 JVM 구현체와 실행 환경은 실행할 운영체제와 CPU에 맞아야 합니다. [근거: JVMS §1.2][jvms]

따라서 다른 컴퓨터로 프로그램을 옮길 때는 그 프로그램을 지원하는 실행 환경을 준비해야 합니다. 프로그램이 요구하는 Java 기능과 라이브러리도 맞아야 하므로, “클래스 파일이면 어떤 환경에서든 조건 없이 실행된다”로 확대해서 이해하지 않습니다. 구체적인 버전 호환 조건은 다음 문서에서 확인합니다.

### JVM이 실행하는 방식을 하나로 단정하지 않습니다

JVM이라는 이름만으로 모든 명령을 반드시 한 줄씩 해석한다고 결론 내릴 수는 없습니다. JVM 사양은 특정 구현 기술을 강제하지 않으며, 실행에 기계어 변환을 활용하는 구현도 가능합니다. 인터프리터와 JIT 컴파일러의 동작은 이후 JVM 학습에서 다룹니다. [근거: JVMS §1.2][jvms]

### 언어를 배우는 일과 도구를 설치하는 일을 구분합니다

JDK를 설치했다고 Java의 문법을 익힌 것은 아니며, Java 문법을 안다고 필요한 도구가 준비된 것도 아닙니다. 이 예제를 공부할 때는 **코드의 의미를 이해하는 일**과 **그 코드를 컴파일·실행할 JDK를 준비하는 일**을 각각 확인하면 됩니다.

## 다른 기술과 연결되는 부분

- **1.2 소스 컴파일, 바이트코드, JVM 실행**: 이번 글에서 구분한 `javac`와 `java`의 역할을 실제 파일과 실행 단계로 확인합니다.
- **1.3 패키지, 클래스패스와 JAR**: JVM에서 실행할 프로그램과 라이브러리를 어떻게 찾고 묶는지 배웁니다.

## 정리

- **Java 언어**는 프로그램을 표현하는 규칙이고, **표준 API**는 프로그램에서 사용하는 공통 기능의 계약입니다.
- **JVM**은 클래스 파일을 실행하는 가상 머신이며, 실제 실행에는 JVM 구현체와 필요한 라이브러리가 함께 쓰입니다.
- **JDK**는 개발 도구와 실행에 필요한 구성을 제공합니다. **JRE**는 실행 환경을 가리키며 JVM 하나와 동일하지 않습니다.

이제 “Java로 작성한 프로그램을 JDK의 도구로 준비하고, 표준 라이브러리와 JVM이 있는 환경에서 실행한다”는 문장에서 각 이름이 맡은 역할을 구분할 수 있으면 됩니다.

## 참고 자료

아래 자료에서 사실과 API 계약을 확인하고 설명 순서·문장·예제를 독립적으로 구성했습니다. 버전이 있는 자료는 Java SE 21 Edition 또는 JDK 21 문서이며, 자료 확인일은 2026-09-06입니다.

1. [The Java Virtual Machine Specification — §1.2 The Java Virtual Machine][jvms]: JVM의 추상적 정의, 클래스 파일과 언어의 관계, 구현 기술과 플랫폼 독립성.
2. [The Java Language Specification — Chapter 1 Introduction][jls-intro], [§1.4 Relationship to Predefined Classes and Interfaces][jls-api]: 언어의 성격, 언어 사양과 표준 API의 구분.
3. [The javac Command][javac], [The java Command][java]: 각 문서의 Description과 `java`의 Standard Options 중 클래스패스 옵션. 예제의 두 명령이 맡는 역할.
4. [System — out][system-out], [PrintStream — println(String)][println]: 표준 출력 스트림과 문자열 출력·줄 종료 계약.
5. [dev.java — Getting Started with Java][getting-started]: Preparing the Execution of Your First Program, Setting up a Java Development Kit의 JDK·JRE와 플랫폼 구현 설명. 계속 갱신되는 학습 자료이므로 설치 예제나 최신 언어 문법은 이 글에 옮기지 않았습니다.
6. [OpenJDK JEP 220 — Modular Run-Time Images][jep-220]: Current run-time image structure와 New run-time image structure. 기존 JRE·JDK 구성과 모듈화 이후 런타임 이미지의 차이를 확인한 역사적 설계 자료입니다.
7. [The jlink Command — Description][jlink]: 필요한 모듈과 의존성을 모은 맞춤 런타임 이미지의 의미.
