# 문서 템플릿

새 문서는 로드맵에서 다음 주제를 선택한 뒤 이 디렉터리의 템플릿을 복사해 시작합니다.

## 템플릿 선택

- `study-note.mdx`: Java처럼 공식 자료를 참고해 직접 공부하고 설명하는 문서
- `translation.mdx`: Spring Framework와 Spring Boot 공식 문서를 선별해 번역하는 문서

## 상태 흐름

1. **작성 전**: 공개 로드맵에만 있으며 실제 문서 파일은 만들지 않습니다.
2. **작성 중**: 템플릿을 `docs/` 아래에 복사하고 `draft: true`로 작성합니다.
3. **작성 완료**: 문서를 검토한 뒤 `draft: true`를 제거하고 로드맵에 문서 링크를 연결합니다.

작성 중인 주제를 공개 로드맵에도 표시하려면 로드맵 상태 변경을 먼저 병합합니다. 짧은 문서는 문서 완성과 함께 바로 `작성 완료`로 변경해도 됩니다.

## 작성 규칙

- 파일명과 경로는 소문자 kebab-case를 사용합니다.
- 페이지마다 기준 버전과 주요 출처를 기록합니다.
- 직접 작성한 해설과 번역문을 문서 유형으로 명확하게 구분합니다.
- 번역문은 원문의 제목 구조를 따르고, 추가 설명은 `TranslatorNote`로 구분합니다.
- 코드 예제는 직접 검증한 최소 예제를 우선합니다.
- 원문의 라이선스와 재배포 조건을 문서별로 확인합니다.
- 본문과 예제 설명에는 로컬 검증 환경의 배포판·세부 버전을 적지 않습니다. 기준 버전만 표기하고, 실제 검증 환경은 PR의 검증 항목에 남깁니다.

## Java 시각자료 작성 규칙

Java 초안의 완료 기준에는 본문뿐 아니라 핵심 개념을 설명하는 시각자료도 포함됩니다. 에이전트가 조사·작성하는 경우 시각자료의 작성과 검증까지 수행하며, 사용자에게 빈 그림 자리만 넘기지 않습니다.

- 의미 있는 시각자료를 최소 1개 포함합니다. 개수 채우기용 이미지나 본문을 그대로 반복하는 장식용 그림은 넣지 않습니다.
- 실행 흐름·상태 변화·상호작용·참조 관계는 직접 작성한 Mermaid 다이어그램을 우선합니다. 단순 비교는 Markdown 표를 사용해도 됩니다.
- 시각자료는 별도 고정 섹션에 모으기보다 `동작 원리`나 `예제` 등 설명이 필요한 위치에 배치합니다. 여러 개가 필요하면 해당 설명 옆에 나눠 넣습니다.
- 그림이나 표 바로 아래에 읽는 순서와 핵심 의미를 짧게 설명합니다. 이미지는 대체 텍스트를 제공하고, 색상만으로 의미를 구분하지 않습니다.
- 공식 이미지는 재사용 조건을 확인한 경우에만 사용합니다. 원문 페이지, 제작자 또는 권리자, 적용 라이선스·허용 조건, 수정 여부를 함께 기록합니다. 조건이 불명확하면 이미지를 복사하지 않고 원문 링크와 독립적으로 구성한 설명·도식을 사용합니다.
- 직접 작성한 도식도 근거 자료를 연결하고, 이해를 위해 생략·단순화한 부분을 설명합니다. 원본 그림의 단순 모사나 번역을 독립적인 도식으로 취급하지 않습니다.
- 그림의 용어·화살표·상태 전이·기준 버전이 본문 및 코드 예제와 일치하는지 검토합니다. 렌더링된 페이지에서 글자 크기, 잘림, 모바일 가독성과 밝은/어두운 테마를 확인합니다.
- Mermaid를 사용하기 전에 사이트의 렌더링 지원을 확인합니다. 지원이 없으면 필요한 설정 작업을 명시하고, 렌더링이 확인되기 전에는 그림이 준비되었다고 보고하지 않습니다.
- 의미 있는 시각화가 어려운 주제는 장식용 자료를 강제로 넣지 않습니다. 생략 이유를 초안의 MDX 주석과 검토 보고에 남깁니다.
